# 2026-10-03

## 新增功能：空战对决（双机 BFM 格斗）

需求：用户在地图点选红/蓝两架战机出生位置 → 专用格斗算法驱动追击咬尾与规避 → 2D/3D 视图展示过程 → 先击落对方者胜。

### 服务端（pro/server）
- 新增 `src/engine/systems/FlightModel.js`：受限转弯率（过载/速度相关）+ 能量交换（盘旋、爬升掉速）、边界自动回转、俯仰/滚转姿态输出。
- 新增 `src/engine/systems/MissileSystem.js`：空空导弹比例导引、**线段最近点近炸判定**（必须做，否则 1100m/s 导弹在 0.1s 子步内穿透目标导致命中率≈0）、干扰弹脱锁概率。
- 新增 `src/engine/ai/AirCombatAI.js`：ATA/AA/enemyATA 态势几何；优先级 = 规避来袭导弹（侧转+干扰弹）> 防御（破S/桶滚/防御急转/盘旋）> 进攻（前置追踪、高/低悠悠、中距锁定发射、航炮射击锥）。
- 新增 `src/engine/systems/AirCombatSystem.js`：编排器，dt=1s 内部分 10 个 0.1s 子步；输出 combatEvents、航迹、duel 态势。
- `CombatSystem.resolveCannon()`：射击锥 + 距离 + 目标机动的命中概率模型。
- `Simulation`：`startDuel/resetDuel/stepAirDuel/pushDuelEvent`；`getState()` 增加 `duel/missiles/trails/category/pitch/roll/maneuver`；对决时 `tickRate` 降到 300ms。
- `server.js` 新增 `startDuel / stopDuel / setDuelStyle` 三个 WS 命令。
- `Database.js`：新增机型 `fighter_heavy`(歼-16)、`fighter_light`(歼-10C)，所有空中单位挂载 `airCombat` 参数块（cannon/missile/turnRate/maxG/climbRate/min-maxSpeed/flares）。

### 关键缺陷修复（否则功能跑不起来）
- **`getEquipment()` 会把 `type` 覆盖成装备键名**（如 fighter），导致旧代码里 `entity.type === 'air'` 全部失效；新增 `category` 字段与 `isAirEntity()` 统一判定。
- `checkEndConditions()` 原来过滤 `type !== 'air'`，纯空战场景第一步就判平局并 stop；改为按阵营存活实体判定 + duel 分支。
- `TerrainManager.getMovementSpeedModifier()` 对 flight 返回 1（水域/山地 pass=0 会让战机速度为 0）。
- `MovementSystem`：新增 `airDrivenExternally` 开关；空中单位跳过地形阻挡与地面 30m 水平排挤。
- `View3D.clearEffects()` 缺失导致 `main.js cleanupAfterGame()` 抛 TypeError（已补齐）。

### 前端（pro/client）
- `index.html` 新增「✈️ 空战对决」面板（机型/高度/风格、点取出身点、对称自动布置、开始/结束、双机跟随、态势条）；CSS 新增 `.duel-*` 样式。
- 新增 `js/AirDuel.js`：面板控制器（点取出身点标记、发送 startDuel/stopDuel、渲染血量/速度/高度/距离/机动/被锁定告警）。
- `Map2D.js`：战机图标按航向旋转（`rotate(90-heading)`）、航迹虚线、🚀 导弹实时标记、`isAirType()`。
- `View3D.js`：`buildAircraft()` 战机模型（机身/机头/主翼/平尾/垂尾/尾焰）、按 z 高度渲染、YZX 欧拉（航向+俯仰+滚转）、3D 航迹线、导弹 mesh、击落爆炸特效、`setFollowDuel()` 双机跟随相机、`clearEffects()`。
- `main.js`：地图点击优先交给 AirDuel；`updateState` 分发 `duel/missiles/trails`；战斗日志新增航炮/导弹发射/脱靶/干扰弹文案。

### 调参结论（实测 8 场：51~124 步，约 15~37 秒）
- `damageScale = 0.3` 同时作用于航炮与导弹（否则一枚导弹直接秒杀）。
- 干扰弹诱骗概率 0.025/子步；规避状态命中惩罚 0.15 → 导弹命中率约 38%，脱锁约 45%。
- 高度用 `clampAltitude()` 限制在巡航高度 ±2500m，避免双方互相爬升到平流层。

### 依赖本地化（修复 CDN 加载失败）
浏览器报 `net::ERR_CERT_AUTHORITY_INVALID` / `ERR_TIMED_OUT`：index.html 的 leaflet.css、leaflet.js、three.js r128、leaflet.polylineDecorator 全部走 CDN（unpkg/cdnjs），在受限网络下不可用，导致 `L`/`THREE` 未定义、整个页面白屏。
- 处理：用 node https 下载到 `pro/client/vendor/`（含 leaflet 的 images/ 目录），index.html 改为本地相对路径；底部新增兜底脚本：检测 `window.L`/`window.THREE`/`L.PolylineDecorator` 缺失时 `document.write` 注入 CDN（保证 vendor 丢失时仍可用）。
- 服务器 `express.static(../client)`，故 `/vendor/*` 可直接访问（已验证全部 200）。
- `Map2D` 新增在线瓦片 `tileerror` 计数，连续 6 次失败自动 `setOfflineMode(true)` 并同步工具栏开关，避免断网时满屏瓦片超时。

### 用户反馈修复：机型/阵营区分 + 2D 战机不跟随
- **图标缺失**：`Map2D.createIcons().shapeMap` 只映射了 `fighter`，`fighter_heavy`/`fighter_light` 落到 `default`（灰方块），所以歼-16/歼-10C 在 2D 上根本不像飞机。已为三种机型各画 SVG（隐身箭形 / 重型宽翼+双垂尾 / 轻型三角翼+鸭翼），并补齐 `uav`、`awacs` 形状与映射。
- **"战机停在初始点"**：服务端实测坐标持续推进（无问题）；用户看到的其实是 `AirDuel` 的起飞点 ✈️ 标记（emoji 不受 color 影响，红蓝看起来一样且不动）。改为 ⚑「红/蓝方起飞点」旗标 + 文字，`startDuel` 后加 `.duel-spawn-faded`（opacity .45），`stopDuel`/`onSimulationEnd` 恢复。
- **新增 `Map2D.updateDuelAircraft(entities)`**：duel 模式下为双方渲染实时跟随标签 ▲红 / ◆蓝（机型+高度+速度，击落显示 ✖），`main.js` 在 `state.duel.enabled` 时调用，`clearDuelVisuals()` 一并清理（新增 `duelAircraftLayers`）。
- **下拉框区分**：`#duelRedType/#duelBlueType` 加 `duel-select side-red/side-blue` 主题色（边框+底色+文字），选项文案标注型号特性，面板加 ▲红/◆蓝/⚑起飞点 图例；`AirDuel` 新增 `DUEL_AIRCRAFT_INFO`（中文名+特性）与 `refreshTypeHint()`，开始日志改用中文机型名而非枚举值。

### 「🗑️ 清空所有」改为真正清干净画布
原 `main.js clearAllEntities()` 只逐个发 `removeEntity`，大量图形残留。现改为：
- 直接发 `clearAllEntities`（服务端 `sim.stop()` + 清空实体/行为树/时间/步数 + `resetDuel()` + 重置 stats + `replay=[]` + `broadcastState()`）。
- 本地依次清理：`attackAnimations.clearAll()`、`view3d.clearEffects()`、`map2d.clear()`、空战 `airDuel.reset()`、取消区域划定、`deleteExerciseArea()`、清空选中态与 statsPanel、清空 `state.entities/duel/missiles/trails` 防残留；回放中先 `stopReplay()`。
- `Map2D.clear()` 扩展：新增 visionCircles / radarCircles / attackLines / `clearAllPaths()` / `selectedId` 重置（地形叠加与演习区域仍单独 `clearExerciseArea` 清除）。
- `AirDuel.reset()`：清起飞点标记、positions、跟随、态势条数值与按钮文案。
- 拖拽划区时的临时矩形原先是局部变量无法清除：改为 `this._tempAreaRect`，`cancelAreaSelection()` 统一移除。

### 页面模块化重构（顶部栏 + 左侧分页）
原左侧面板是 9 个 section 长列表，过于杂乱。参考成熟软件改为「顶部全局区 + 左侧模块分页 + 右侧监视区」：
- **顶部栏**：品牌；推演控制（开始/停止/单步/重置）；视图切换（viewMode select）+ 显示开关（标签/射程/地形 三个 checkbox）；想定文件操作（加载/保存/清空所有）；右侧运行状态芯片（时间/红军/蓝军/实体 + 连接状态）。
- **左侧**：4 个 tab —— 📝想定（模式、演习区域、想定编辑器、预设想定）、✈️空战（原空战面板整体）、👁️视图（底图/离线/缓存 + 图例）、🤖AI（AI 配置）。切 tab 逻辑在 `main.js initSidebarTabs()`（`data-tab` / `data-panel` 配对，`.active` 切换）。
- **右侧**：单位实时状态 → 视角跳转（红/蓝方位置）→ 战损统计（5 张 stats-card）→ 推演回放 → 推演日志。
- 补上了 `btnResetArea` 按钮（JS 早已绑定 resetExerciseArea，但 HTML 里一直缺这个按钮）。
- CSS 关键点：`body` 改 flex column、`.header` 高度自适应、`main-container` 改 `flex:1`（原来写死 `calc(100vh - 48px)` 会因顶部栏换行溢出）；`.control-panel` 改 flex column + `.tab-panels` 内部滚动；**必须**用 `.stats-panel .panel-section h3` 覆盖原 `.stats-panel h3`（居中 16px 大标题）否则右侧小节标题全被放大。
- 重构时保持所有元素 id 不变（JS 全部按 id 取值），已逐一核对无缺失。

### 结束弹窗合并为一个
原来推演结束会同时弹两个框：`StatsPanel.showEndGameModal()`（结果 + 保存回放）+ `main.js showEndGameDialog()`（胜负 + 伤亡 + 保存/跳过）。
- 删掉 `StatsPanel.showEndGameModal` 及其 `endGameModalShown` 字段，`checkConclusion()` 只把结论文案写进右侧「推演结论」卡片。
- `main.js showEndGameDialog()` 成为唯一弹窗：图标 + 红/蓝/平局标题（按 `side-red|side-blue|side-draw` 主题色）+ 结束原因 + 双方伤亡 + 三按钮：💾 保存回放（保存后清理）/ 🗺️ 留在战场（只关闭，保留最终态势）/ 🧹 清理场景；点击遮罩等同"留在战场"。
- 触发条件放宽为 `!isRunning && !replayPlaying && (stats.winner || stats.endTime)`，并在 `isRunning` 时把 `_endDialogShown` 置 false（保证下一轮还会弹）。已确认服务端 `loadScenario()` 会 `resetStats()`，重置后不会误弹。
- CSS：`.endgame-*` 整块替换为 `.result-modal*` 样式。

### 验证方式
- 无头：`node -e` 直接 require Simulation 跑 `startDuel` 循环 `step()` 统计步数/胜负/武器分布。
- 端到端：`node -e` 内 `spawn server.js` + `ws` 客户端发 `startDuel`，观察广播的 duel/missiles/trails 直到 winner。
